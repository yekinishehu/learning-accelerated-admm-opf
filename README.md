# Learning-Accelerated ADMM — Reproducibility Artifact

This repository contains the code, training data, trained checkpoint, frozen protocol, raw experimental evidence, verification outputs, and regenerated manuscript assets for:

**Learning-Accelerated ADMM: Convergence Theory and Application to Stochastic Optimal Power Flow**  
Yonghong Yao and Yekini Shehu  
Manuscript: **ELSCAM-D-26-03479R2**

The reported study is **`strengthened-cold-v1`**. It contains 45 runs on 15 instances: scenario counts \(S\in\{20,50,100\}\), seeds 99–103, and algorithms `exact`, `ml`, and `hybrid`. Every exact ADMM iteration and every exact-tail iteration uses cold scenario-QP solves, with \(\rho=0.01\).

The older twelve-run `final-cold-v1` study is not part of this repository's reported evidence.

## What is included

- `code/`: ADMM/DRS implementation, batched interior-point solver, scenario generation, RNN predictor, training, certificates, analysis, verification drivers, IEEE 118-bus data, and the executed checkpoint `proxy_clean.pt`.
- `experiments/`: grid execution, structural replay, training replay, and numeric-macro finalization scripts.
- `training_data/`: all 30 training shards, containing 2,024 feature/label pairs.
- `results/runs/`: 45 raw NPZ archives, 45 JSON summaries, 45 per-run manifests, and 10 retained I/O-failure records.
- `results/`: verification reports, execution/training logs, retry records, analysis output, and complete 45-row CSV/Markdown grid reports.
- `manuscript/generated/`: numerical macros, four generated tables, and three vector figures used by the manuscript.
- `strengthening_protocol.json`: frozen evaluation grid, numerical settings, and analysis/failure policies.
- `VERIFICATION.md`: final referee-comment and reproducibility audit.
- `SHA256SUMS`: SHA-256 checksums for the repository artifacts.

## Reference environment

The per-run manifests record Python 3.12.12, NumPy 2.2.5, and PyTorch 2.8.0. Figures were generated with Matplotlib 3.10.3. Single-thread numerical execution is required for the recorded deterministic replay checks.

```bash
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1
```

The recorded bitwise checks were passed in the reference environment. Array-level replay can depend on the Python, NumPy, PyTorch, BLAS, operating-system, and hardware environment. Wall-clock times are descriptive measurements and are not expected to reproduce bitwise on another machine.

## Integrity check

Run this before executing scripts that rewrite verification reports:

```bash
sha256sum -c SHA256SUMS
```

On macOS, use `shasum -a 256 -c SHA256SUMS` if available. The manifest covers the archived artifact files; it does not cover files subsequently generated by verification or analysis commands.

## Verify the supplied evidence

From the repository root:

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
python3 code/verify_final.py
python3 experiments/verify_structural.py
python3 experiments/verify_training_replay.py
```

These checks cover:

- source, protocol, raw-NPZ, and summary hashes;
- NPZ schema, archive integrity, and finiteness;
- exact terminal-residual recomputation;
- independent certificate evaluation for all 45 runs;
- bitwise standalone/hybrid ML identity for all 15 instances;
- bitwise full-ML replay from the executed checkpoint for all 15 instances;
- bitwise cold exact-tail replay for all 15 instances;
- exact ML component mean/sum accounting for all 30 ML/hybrid runs;
- bitwise replay of all 30 training shards and every checkpoint tensor/normalization array.

The verification commands rewrite their corresponding JSON reports. Use `git restore` to return to the archived versions after a local replay, if needed.

## Regenerate tables, figures, and macros

Only run the analysis after the verification gates pass:

```bash
python3 code/analyze_results.py
python3 experiments/finalize_numeric_macros.py
```

The second command makes digit-containing TeX macro names safe and derives `NumIORetryCount` directly from `results/io_retries.json`. Its value is **10** for the archived study.

## Execute individual runs or the grid

To execute one instance into a separate output directory without overwriting the archived evidence:

```bash
python3 code/run_one.py \
  --S 50 --seed 99 --algo hybrid \
  --out rebuilt_runs --rho 0.01
```

To execute missing runs from the frozen grid:

```bash
python3 experiments/run_strengthened.py
```

The grid driver skips complete run triples already present in `results/runs`. For a completely fresh execution, work in a separate copy with an empty `results/runs` directory. Do not replace seeds or numerical settings after inspecting results.

## Reported outcomes retained without selective filtering

- All 30 exact/hybrid runs satisfy \(r^K\leq10^{-4}\) and \(s^K\leq10^{-4}\).
- All 15 fixed-proxy ADMM-ML runs stall and remain uncertified; terminal consensus residuals span 2.282–8.181 MW.
- At \(S=20\), all five hybrids are slower: signed speedups range from −74.16% to −25.30%.
- At \(S=50\), all five hybrids are faster: 11.31% to 16.10%.
- At \(S=100\), all five hybrids are faster: 12.12% to 19.87%.
- Five paired seeds per scenario count provide descriptive, not confirmatory, timing evidence. No universal acceleration claim is made.

See `results/45_run_final_grid.csv` for the complete per-run data and `VERIFICATION.md` for the final audit and solver-quality limitations.
